# Madhav Split Reels

**Teach on top. Madhav below.** Reuse the AI-course Reel's actual design and motion system with a new topic, not a frozen screenshot or generic split-screen approximation.

## Start here

Read the current project's instructions and checkpoint. Use only identity photos and footage the presenter has approved. This skill does not grant generation, spending, likeness-transfer, upload, scheduling or publication approval.

Read [style-and-motion.md](references/style-and-motion.md) for every new use. It defines exact geometry, typography, easing, reveal behavior and retiming. Use [split-style.css](assets/split-style.css) and [split-preset.json](assets/split-preset.json) as source-backed implementation inputs. They are not a standalone renderable project.

Inspect [the rendered reference](../../docs/madhav-split-reels/storyboard.jpg) for framing and visual hierarchy. The thumbnail of a scheduling editor is not the design source.

## Reuse workflow

1. **Choose the lesson.** State audience, useful decision, truthful hook, three checks or steps, concrete proof/example and complete CTA. Use [topic-brief.md](assets/topic-brief.md). Do not force a three-check structure onto a topic that needs a real demonstration; offer the appropriate format instead.
2. **Lock what stays.** Keep the three-zone layout, neutral palette with restrained blue, large presenter, short black captions and speech-timed teaching motion. Change every topic-specific claim, icon, example, label, narration and cover headline together. Existing master/source remain read-only; create a new dated project.
3. **Finish speech before animation.** Read [production-and-qa.md](references/production-and-qa.md) for voice, presenter, music/FX and hard failure conditions. Use verified new audio timings, not the AI-course timestamps. The reference's 1.2x audio is already accelerated; never double-speed the presenter.
4. **Implement the motion recipe.** For video authoring, load the current `hyperframes` routing skill and your editorial skill (for example video-use, if installed), then the relevant engine skills. The editorial skill owns the plan. All reference scenes and final assembly used HyperFrames 0.8.63; preserve that pin when reusing that source. Record engine choice per scene; do not force Remotion into a purely HyperFrames edit.
5. **Review one moving beat, then finish.** Check a comparison/diagram beat with real speaking video and audio, not only an attractive still. Keep settling/reading time. Complete the remaining scenes, native Image Gen cover when requested, caption and playable master; no more than three creative passes per requested batch without further authorization.
6. **Verify and hand off.** Apply the production/QA checklist to the actual encoded output. Report technical, content, visual/identity, listening/lip-sync and user-acceptance states separately. Deliver a local reviewable package by default. Load the delivery section only when upload/scheduling is requested.

## Style boundaries

- This is a large lower presenter and upper illustrated lesson, not the `ai-demo-reel` corner-presenter/browser-demo format. Keep that sibling skill for real UI demonstrations.
- The upper panel remains in place while lesson content changes. Preserve sequential reveals and drawn checks; do not replace them with empty cards, neon, bounce loops or stock robot clips.
- Captions are short phrase-level black text, not karaoke color flashes or a dark band. Keep eyes, mouth and gestures clear.
- Prefer the presenter's verified existing office/computer look for an exact-style request, unless the user chooses another. Do not use a static portrait as finished footage.
- New topics need new review; the historical file's measurements and scheduling state do not transfer to a new Reel.
